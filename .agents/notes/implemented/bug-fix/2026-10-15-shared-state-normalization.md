# Agent Note: 共享前缀状态只计算一次概率归一化

Status: implemented

## Problem

完全命中已复用完整运行结果，但分叉候选从同一前缀续跑时仍重复计算该隐藏状态的全词表投影和 log-sum-exp。已有 KV 和隐藏状态复用没有保留与目标 token 无关的归一化常数。`log_probability` 为一个 token 构造完整分布，还遍历词表扣除所有不使用的分数。

## Decision

隐藏状态由 `Arc<HiddenState>` 共享，并用 `OnceLock<f32>` 按需记录完整词表投影的归一化常数。目标 token 只单独计算它的 logit，再减去相同常数。初次初始化沿用原来的点积、最高值、指数求和顺序；`distribution` 对完整词表的公开行为保持不变。`resume`、`joined` 共享同一隐藏状态及归一化缓存，生命周期继续受上一轮候选约束。使用 Rust 1.70 起稳定的 `OnceLock`，保留 1.75 MSRV 和 Send/Sync。

## Existing decisions

[完全命中缓存](../../implemented/bug-fix/2026-10-15-identical-rerank-cache.md)部分重叠，继续持有上一轮完整运行；本篇补全部分共享状态的归一化复用，不翻转它的决定。活跃笔记中没有其它归一化缓存方案或需要废弃的提案。

末位置的前向由[候选末位置按需计算](2026-10-15-defer-terminal-forward.md)补充：缓存保留完整累计分，KV 和隐藏状态在续跑经过末 token 时补齐；本篇的共享与失效约束继续成立。

## Alternatives considered

- 缓存每个位置的完整分布：命中后读取最快，但内存随词表大小乘候选位置增长，键盘扩展承担不起；只保存一个 f32 常数。
- 只缓存已提交上下文：最容易接入，但候选共享前缀后的续跑状态仍重复投影，不能覆盖已定位的分叉重复工作。
- 提前计算每个隐藏状态的常数：不需要延迟初始化，但每条候选末字通常不预测下一个字，会为未使用的状态增加一次完整词表开销。
- 单线程 Cell/Rc：内部状态便宜，但会破坏现有公开重排器的 Send/Sync 能力。

## Verification

实际词表投影计数回归在旧实现失败（4 次而非 3 次），修复后共享上文为 3 次、两条同位置续跑为 1 次、再用已知位置为 0 次，换上下文重新计算。非均匀合成权重覆盖单 token 与完整分布位模式、越界 token clamp 和末位置不提前投影。既有 f32/f16/int8 序列回归覆盖缩短、恢复、重排、重复、空、未知字符与窗口截断，继续保持 Send/Sync。

固定旧提交 `2bd674a9972ee44c87c7b06e87a90efe35095316` 和真实模型 SHA256 `86ac529510cb3b4968a5e6ade83ec8080f5b34a0a681e75c362accbbd387d1c1` 同进程对照：141 条全拼、81 条九键，缩短、恢复、重复、倒序、恢复共 1110 轮、9980 个评分逐位一致；冷 score 与完整公开分布也逐位一致。全拼词典桶 9/9、解码器桶 104/131，九键词典桶 7/7、解码器桶 43/74，旧新全部相同。这里只验证既有门控回放，不改变宿主判据。

Rust 1.97.1 与 MSRV 1.75 各通过 28 项测试（14 单元、14 集成）；全目标 Clippy、fmt 与 diff 检查通过。临时固定旧实现的审计与配对测量程序只用于本机验证，未进入分发源码。

## Measurements

固定上述 4.5 MB 模型，`bench <模型> eval/sentences-v1.tsv`，60 条合成用例，每形状 40 次。没有同时运行本任务的编译、测试或其它 benchmark，但机器其它任务仍造成明显抖动；完整表保留，不把两次独立运行的 p95 差归因于改动。长句不足时按工具既有规则重复候选，0.000 是显示精度。新增的末字交替表检查甲、乙都是已知 token，防止 UNK 导致假命中。

## Consequences

每状态只保留一个 f32 常数，缓存内存不随词表大小乘候选位置增长。每个新隐藏状态多一个小 Arc 分配和 OnceLock；第一次只取一个 token 时多算一次目标点积。末位置按需投影，避免没有后继 token 时的额外工作。公开分布与缓存概率沿用原点积和归一化次序；缓存不改变候选预算、门控、权重或资源。主项目仍需单独验证质量和逐键延迟，不能用微基准声称九键满足 16 ms。
