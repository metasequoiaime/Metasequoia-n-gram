# Agent Note: 全词表投影按精度遍历权重行

Status: implemented

## Problem

固定上游 `362bf56` 的主项目九键二十秒采样中，`Matrix::dot_row` 有 2934 个栈顶样本，是最大单一热点。`project` 为同一隐藏状态完整遍历词表，每行重复通过权重精度分派和切片范围计算，仍是采样中的实际调用者。采样扰动后的延迟不能当成无采样预算成绩。

## Decision

只在 `SentenceModel::project` 按 Float / Quantized 匹配一次，再按行顺序遍历完整词表权重，直接计算 logit、最高值并写入原 logits。八路点积、逐行缩放、最高值与指数求和顺序保持；不改通用线性层，不展开量化权重常驻，不新增依赖或 unsafe，维持 Rust 1.75。

## Existing decisions

已检索活跃笔记中的 `project`、投影、行分派和矩阵。[通用行分派负结果](../../rejected/bug-fix/2026-10-15-matrix-row-dispatch.md)部分相关，完整线性层的闭包写入没有通过预算，本片不翻转它；该笔记明确留下 `project` 未验证，不能把无 bias 的原型成绩作为本片证据。[四行交错](../../rejected/bug-fix/2026-10-15-matrix-row-batching.md)继续否定改变计算调度；[共享归一化](../../implemented/bug-fix/2026-10-15-shared-state-normalization.md)继续规定状态的投影与缓存寿命。KV 拆分和借用只管存储，没有完全吸收或过时提案。

## Alternatives considered

- 复用通用行遍历闭包：可以统一 linear 与 project，但真实线性层已有负结果，本片直接验证 project 的完整投影与归一化，不引入未证明收益的通用层。
- 扩大每行累加路数或分组输出行：可能提高计算并行度，但已有舍入或寄存器重排问题，且会重走已否路线。
- 保持逐行分派：代码最短；若完整投影配对不能证明收益，保留它并记录负结果。

## Verification

固定 `362bf56` 的完整旧 project 正文，只转换接收者和测试计数器路径；先逐位比较全部 logits 与 normalizer。单测覆盖 Float / Quantized、宽 1/7/8/9/192/768、词表 3/9/257。配对测试包含结果分配、最高值、指数归一化与析构，每形状 40 对、每臂 50 次、交替先后，全部形状收集完统一断言。预先预算为量化 192 主形状小于 0.99、其他小于 1.03，没有放宽或挑选样本。

| 精度 | 宽 | 词表 | 旧生产路径比值 | 最终新路径比值 |
| --- | --- | --- | --- | --- |
| int8 | 192 | 8192 | 0.9982 | 0.9613 |
| float | 192 | 8192 | 0.9904 | 0.9550 |
| int8 | 768 | 8192 | 0.9980 | 0.9848 |
| float | 768 | 8192 | 0.9989 | 0.9907 |

旧生产路径真实未通过主形状预算；最终新路径通过。独立审查发现加载阶段只检查总元素数，量化文件形状首维与运行时行数可不同，导致 zip 静默缩短。现在加载时检查 tok/qkv/proj/fc/out 的 scale 数与运行时输出行数一致，project 也先限定 scale 切片。回归对五类矩阵各减半/翻倍行数、保留总元素数且保持文件 shape 与 scale 一致；旧加载器实际失败，新版通过。仅靠投影处切片可避免静默错误，但会延后到推理时报越界，故在加载边界返回 Geometry 错误。

Rust 1.97.1 和最低 1.75.0 各 33 项单测、15 项模型文件测试与 doc tests 通过，1 项性能测试平时 ignored；全目标 Clippy `-D warnings`、fmt 和差异检查通过。独立只读复查确认原问题解决，无新增阻塞。

## Consequences

完整词表按精度只分派一次，保留逐行点积、缩放和归一化顺序；不改通用 linear、权重表示或缓存寿命。局部配对证据支持主形状约 3.9% 的投影收益，完整模型结果仍不能换算成九键 16 ms 达标；主项目另固定提交验证质量、真实延迟与 quick。加载现在拒绝原本可误收的量化行数不匹配文件。独立微基准的函数布局可能不同于发布构建，收益界限必须与主项目延迟一并解释。
