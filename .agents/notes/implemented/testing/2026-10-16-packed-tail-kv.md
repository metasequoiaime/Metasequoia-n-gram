# Agent Note: 尾部前向直接拆分到最终 KV 存储

Status: implemented

## Problem

`run_tail_states` 每层先分配短 K、V，再复制可见前缀并追加这两个短数组。追加还会让已复制的前缀缓冲几何扩容，短尾部保留接近两倍前缀容量；拆分中间数组只用于下一步复制。

## Decision

私有 `split_qkv` 接收可见前缀切片，按最终长度申请 Q、K、V，直接把新位置写入最终 K、V。独立上文传空切片，尾部入口先按 `length * n_embd` 截断旧 KV。保留行序、所有浮点运算、隐藏状态与缓存寿命，不增加依赖或 unsafe，维持 Rust 1.75。

## Existing decisions

已检索活跃笔记中的 `capacity`、预留、`split_qkv`、前向缓冲、追加和 KV。[普通前缀借用](../../implemented/testing/2026-10-16-resume-kv-borrow.md)部分重叠，继续持有可见长度契约；[末位置按需前向](../../implemented/bug-fix/2026-10-15-defer-terminal-forward.md)继续规定末位置缓存仅保存新增一行。分数与外层状态缓冲处理独立容器；矩阵行分组和分派是已否定的计算调度路线，本片不改变矩阵计算。没有完全吸收或过时提案。

## Alternatives considered

- 只为旧前缀精确预留最终容量：改动最少，可消除扩容，但仍先生成并复制两个仅供追加的 K、V 临时数组。
- 持久化跨轮前向工作区：可以复用更多临时缓冲，但要重新约束模型共享与同步调用的可变状态；本片先消除确定存在的中间复制。
- 把 QKV 保持交错布局传给 attention：可以去掉全部拆分，但需要改变 attention 的索引契约，扩大本片范围。

## Verification

`a_short_tail_does_not_double_the_retained_kv_capacity` 在旧实现真实失败（实际保留 40 个元素，只需 24），新实现通过。直接拆分测试按位比较 Q、K、V，覆盖空与非空前缀、零行、两行以及负零；既有续跑对照继续覆盖可见前缀截断与末位置。Rust 1.97.1 和最低版本 1.75.0 各通过 32 项单测、14 项模型文件测试与 doc tests；全目标 Clippy（`-D warnings`）、Rustfmt 与笔记树/格式通过。独立只读审查未发现阻塞问题。

官方 [Vec 文档](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.with_capacity)确认提前申请容量的接口；实际容量回归在本机分配器上验证。首次基准尾段与编译重叠，整轮弃用；保留结果来自全部编译终态后串行执行的两套 release 二进制。

## Consequences

前缀与新行的边界可能错位，借用缓冲中的未来位置必须在调用前截断。Vec 实际容量由分配器决定，本机回归约束现用全局分配器下不因几何增长保留多余 KV 容量；这是内存回归，不能替代真实计时。

每个非空尾部的每层少两个短 K、V 临时数组，并避免最终 KV 的追加扩容；KV 内容和浮点计算不变。helper 增加两个前缀切片参数，独立上文传空切片。后续[末位置两段借用](2026-10-17-terminal-prefix-view.md)省去中间拼接，最终 KV 仍沿用本篇的顺序和精确容量，不改变缓存寿命；主项目需单独固定合并提交并验证质量、延迟和 quick，不能由局部测量声称九键 16 ms 达标。

## Measurements

固定模型 SHA-256 为 `86ac529510cb3b4968a5e6ade83ec8080f5b34a0a681e75c362accbbd387d1c1`；同一九键 81 句数据，每形状 40 次。旧提交 `093f4a2` 与本片 release 二进制串行测量。冷计算九候选十二字 p50 从 45.32 ms 到 46.55 ms，热续跑同形状均为 0.032 ms；前后各一轮，不能据此宣称延迟改善。十五字决策列无样本，零值无效；逐键十五字行也不能解释为完整十五字形状。

为排查冷计算差异，用同一进程固定旧版/新版真实 helper（旧臂包含拆分及前缀复制追加），每形状 40 对、每臂 500 次，奇偶轮交替先后，每形状先比较输出一致。覆盖宽度 64/128/256、行数 1/4/12、前缀 0/1/8/20 个位置。非空前缀的新版/旧版 p50 比值 0.286–0.494；空前缀 0.615–1.024，最慢差约 1.6 ns。局部构造没有解释整轮冷计算约 3% 差异的成本；这不足以证明端到端变快，本片收益是已验证的临时数组删除及持有容量缩减。配对程序使用标准库 `black_box`、release 优化，未新增依赖或 unsafe。
