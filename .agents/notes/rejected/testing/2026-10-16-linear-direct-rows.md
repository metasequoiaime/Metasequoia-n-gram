# Agent Note: 写入型线性层直接按精度遍历权重行

Status: rejected — 当前固定二进制已经在循环外分派精度，未实施新循环

## Problem

主项目固定 `01edc14f05`、本库固定 `6ce2cbb5` 的二十秒九键采样中，`linear_into` 有 1799 个栈顶样本，`dot_i8` 有 1049 个，仍是最大模型热点；attention 栈占比很小。源代码逐输出调用 `Matrix::dot_row`，起初怀疑它在同一次线性层里重复分派精度；后续反汇编否定了该固定二进制上的重复分派假设。权重范围与 scale 索引仍存在，但尚无证据表明改写它们有足够收益。采样后的延迟不能用于无采样预算。

## Proposal

仅在现有 `linear_into` 入口匹配一次 Float/Quantized，直接遍历本次完整权重行、scale、bias 和输出槽，不经过通用闭包行遍历抽象。输入各行顺序、八路部分和、缩放、bias 与输出写入顺序保持；保留拥有型 linear 包装、前馈缓冲和全部缓存契约，不新增依赖、unsafe 或提高 MSRV。

## Existing decisions

已检索活跃笔记中的 `linear_into`、直接行遍历、精度循环、矩阵分派与交错。[通用行分派负结果](../../rejected/bug-fix/2026-10-15-matrix-row-dispatch.md)部分相关，其原型经通用行访问闭包写调用者的槽，完整线性层未过预算；本次在已落地的写入型 helper 内直接实现精度循环，不复用那个抽象，也不拿无 bias 原型的成绩作证据。[词表投影行遍历](../../implemented/testing/2026-10-16-project-row-stream.md)提供同仓库已工作的按精度直接遍历范式；[前馈缓冲](../../implemented/testing/2026-10-16-feed-forward-scratch.md)提供当前 helper 边界。本片若成功只替换旧笔记对通用抽象的局部取舍，不翻转四行交错、32 展开、固定宽和常驻展开权重的负结果。没有完全吸收或过时提案。

[slice 官方文档](https://doc.rust-lang.org/std/primitive.slice.html#method.chunks_exact)已核对 `chunks_exact` 的完整块与尾部契约；显式限定矩阵、scale 与 bias 范围，避免 zip 静默截断。空行和零输出保持原来的空计算。

## Alternatives considered

- 再用通用回调统一 project 与 linear：能减少重复代码，但已有完整调用预算失败，直接循环可避开回调写入和重复索引。
- 优化 attention 或继续复用小缓冲：可以减少申请，但当前采样模型计算主要在线性层，本次优先验证最大热点。
- 改点积路数、交错输出或展开 int8：可能提高吞吐，但已有性能负结果、归约舍入或键盘扩展内存约束，不重走。

## Acceptance criteria

先冻结 `6ce2cbb5` 的完整旧 linear 与写入 helper，在未改生产实现时运行同一生产入口预算，必须真实未通过；再实施直接循环。Float/Quantized、宽 1/7/8/9/192/768、空输入、零输出、多输入行、奇数输出及四种投影几何逐位一致；真实模型评分/分布逐位对照。

release 完整线性层包含输出申请、scale、bias、写入和析构；基宽 192/768 × qkv/proj/fc/out × 输入行 1/4/12 × Float/Quantized，共 48 形状。每形状 40 对、交替先后，旧臂校准至少 10 ms，量化基宽 192 的 12 个主形状全部须小于 0.99，其余全部小于 1.03。全部形状收集后统一断言，不筛形状或放宽预算。未通过则删除实现和临时测试，只合并负结果笔记；通过后再运行完整模型整表、Rust 1.75、全套测试、Clippy、fmt、笔记和独立审查，上游合并后固定提交接入主项目的质量、九键四轮和 quick。

## Risks

两段精度循环增加代码体积，编译器布局可能使一些形状变慢。局部门禁通过不能推断端到端达到 16 ms；直接 zip 必须完整覆盖所有输出，不得静默缩短。只在无并行构建时采用配对预算，受干扰整轮保留并作废。

## Investigation and decision

在实现新循环之前检查主项目 `01edc14f0571953f167808f8079b9728f19bc74e` 的 ARM64 release 二进制，上游固定 `6ce2cbb5b76e189a1ef6ff11eaa0435bfd9983a0`。二进制 SHA-256 为 `0a0cd5e3edab56480a244b3b2b370a2e67732866627b1ea94130ca38b558ae5d`。使用下列命令反汇编真实生产入口，Mach-O 符号需要两个前导下划线；采样地址带 ASLR，不能直接用于静态地址反汇编。

```sh
xcrun llvm-objdump --disassemble-symbols=__RNvCs6BpsVHCHhc3_14chinese_ime_lm11linear_into target/release/examples/rerank_latency
```

关键静态指令如下。`0x10037693c` 的精度判断先于输入行循环 `0x10037697c` 与输出行循环 `0x1003769d0`，另一精度路径跳到 `0x100376bb0`。编译器已经完成主要提议中的循环外分派，不能从源代码调用形式推断它每行重复分派。

```text
100376920: ldr x9, [x2]
10037693c: cmn x9, #0x1
100376940: b.eq 0x100376bb0
10037697c: add x25, x13, #0x1
1003769d0: add x15, x28, #0x1
```

量化点积内环 `0x100376a04` 至 `0x100376a30` 已含向量 `tbl`、`scvtf.4s`、`fmul.4s` 与 `fadd.4s`。本结论只适用于上述固定二进制，不推及所有架构或工具链，也不证明其余线性层优化没有收益。

临时冻结旧 helper 的逐位对照测试通过（1 项）；旧生产路径对冻结旧路径的 48 形状预算运行中观察到 849 次并行构建，内部测试退出 101，整轮作废，不产生性能结论。它从未包含新的直接循环实现，不能称作新方案预算失败。没有实施生产变更，已删除临时测试与模块登记，不重跑已失去主要假设的预算。

## Consequences

保留现有生产代码，避免增加两套精度循环与相应维护成本；代价是线性层热点仍未解决，九键 16 ms 目标仍未达到。下一步调查采样中候选复制与分配的具体调用链；未来若有不同工具链的实际机器码或范围检查成本证据，可以重新提出新方案。
