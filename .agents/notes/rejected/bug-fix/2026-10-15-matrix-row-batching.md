# Agent Note: 量化矩阵按输出行分组计算

Status: rejected — 安全 Rust 原型在当前 ARM64 编译结果上回退 61%–74%，不接入生产

## Problem

当前九键采样中 `Matrix::dot_row` 有 1023 个栈顶样本，是最大的单一热点。ARM64 反汇编显示已使用向量指令，但每次仅有一行的八个部分和（两个向量累加链），输出行逐行完成。线性层和完整词表投影的每一行重复加载同一个输入向量，独立输出之间没有交错调度。

## Proposal

先用固定原始点积作配对微基准，检验四行量化点积交错是否真正提高吞吐。若有效，矩阵批量输出路径按四行分组，输入分块共享，每行保留原来八部分和的加法与最终归约顺序，尾部和不足四行回到原路径。权重继续保留 int8，逐行 scale 不变，不使用不安全代码、特定架构指令或新增依赖；浮点权重沿用原点积。线性层与词表投影复用同一批量入口。

## Existing decisions

[共享归一化](../../implemented/bug-fix/2026-10-15-shared-state-normalization.md)部分重叠，继续约束概率与缓存；本篇只改变一次投影内的矩阵计算调度。完全命中笔记持有缓存寿命，无关行内计算。没有完全吸收或过时提案。上游 int8 常驻约束来自 PR #24，继续保留。

## Alternatives considered

- 增加每行部分和数量：可以增加独立流水线，但改变浮点归约顺序，本轮优先检验跨行交错能否在保持位模式的同时提速。
- 展开全部 int8 权重为 f32：避免重复转换，但上游已因键盘扩展内存限制拒绝，不能靠更大常驻内存换延迟。
- 手写 NEON/AVX 内核：可以直接控制寄存器，但引入不安全代码、架构分支和平台验证负担。先验证安全 Rust 能否满足这一局部优化。

## Measurements

固定 `f4d41421f8633d8899cdb8ed6d6a3207c5e980f7` 的原始 `dot_i8`，合成非均匀权重，每形状 80 对、每对每臂 50 次矩阵计算，奇偶轮交换顺序，均为 release。每个原型输出先与原点积逐位比较，再计时。没有同时运行本任务编译、测试或其它 benchmark。

四行分组的第一版按 lane 交错四个输出，第二版先完成每行的八 lane 更新。两版都保留原来每行的加法顺序，但编译器跨输出行打包，反汇编出现多条跨寄存器 `tbl` 重排；第二版未改善。这里的反汇编分析是对本机构建结果的解释，不推广到所有编译器。

## Acceptance criteria

相对固定逐行基线的配对测试证明量化热点有收益；三精度与奇数宽度/行数、空输入及尾部的结果位模式不变。真实模型评分、门控桶和完整质量对照，完整 benchmark 表与九键逐键测量；Rust 1.75、测试、Clippy、fmt 和主项目 quick 通过。无收益则删除原型，不接入生产。

## Risks

交错更多行可能增加寄存器压力，部分架构不一定更快。输出缓冲的初始化成本也可能抵消小形状收益。性能结论必须区分内核、完整模型与宿主逐键路径。
